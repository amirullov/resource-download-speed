# SDD: измерение скорости загрузки ресурса

## 1. Цель и границы задачи

Разработать консольный скрипт Python, который принимает URL, выполняет 10 последовательных загрузок ресурса методом GET, полностью считывает каждый ответ и выводит среднее время запроса, общий объём данных и среднюю скорость.

**Требования задания:** ровно 10 успешных логических загрузок, последовательное выполнение, подсчёт фактически прочитанных байтов, потоковое чтение, вывод результатов в консоль. Для сдачи нужны публичный GitHub-репозиторий и README.

**Принятые решения:** Python 3.11 или новее, только стандартная библиотека, один обязательный аргумент URL, фиксированные размер блока и тайм-аут. Поддерживаются HTTP и HTTPS.

В решение не входят прогрев, HEAD-запросы, повторы, параллельность, сохранение ресурса, конфигурационные файлы, авторизация и инфраструктура. Измеряется скорость загрузки конкретного ресурса в текущих условиях, а не предельная пропускная способность интернет-канала. Влияние сервера, кешей и сети специально не устраняется.

## 2. Выбранный подход

Использовать `urllib.request` для HTTP, `argparse` для CLI и `time.perf_counter` для монотонного измерения времени. Стандартной библиотеки достаточно; дополнительных зависимостей не требуется.

Минимальная структура:

- `download_speed.py` — весь рабочий код;
- `test_download_speed.py` — проверки на `unittest` с локальным HTTP-сервером;
- `README.md` — запуск и трактовка результатов;
- `SDD.md` — этот документ.

Основные функции:

- `parse_args()` — разбор аргумента и проверка URL;
- `download_once(url)` — одна полная загрузка, возвращающая длительность и число прочитанных байтов;
- `calculate_metrics(results)` — расчёт итоговых показателей;
- `main()` — цикл из 10 загрузок, обработка ожидаемых ошибок и вывод результата.

Сетевое чтение сосредоточено в одной функции. Классы и дополнительные слои для рабочего кода не нужны. Число загрузок, размер блока 64 KiB и тайм-аут 30 секунд заданы константами.

## 3. Контракт CLI

Запуск:

```text
python download_speed.py https://example.org/image.bin
```

URL — обязательный позиционный аргумент. Проверяются схема `http` или `https`, наличие имени хоста и корректность порта. Некорректные значения отклоняются до сетевого обращения. Фрагмент URL не участвует в HTTP-запросе. Параметр `--help` показывает справку.

Пример успешного вывода для десяти ответов по 1 MiB и суммарного времени 5 секунд:

```text
Успешных загрузок: 10
Среднее время запроса: 0.500 с
Общий объём: 10485760 байт
Средняя скорость: 2.000 MiB/s
```

Итог выводится в stdout только после всех 10 успешных загрузок. Время и скорость округляются до трёх знаков; расчёты используют исходную точность.

Коды завершения:

- `0` — успешный замер; также штатный выход по `--help`;
- `2` — ошибка аргументов или неверный URL;
- `1` — HTTP-ошибка, сетевая ошибка, тайм-аут или обнаруженное неполное чтение;
- `130` — прерывание пользователем через Ctrl+C.

При первой ошибке выполнение останавливается без повторов. В stderr выводится короткое сообщение с номером загрузки и причиной, например: `Загрузка 4/10: HTTP 404. Замер не завершён.` Частичные результаты не представляются как успешный замер. Ожидаемые ошибки обрабатываются без traceback; программные ошибки не маскируются общим перехватом всех исключений.

## 4. Алгоритм и измерения

После проверки URL выполняется цикл из 10 итераций:

1. Подготовить GET-запрос с `Accept-Encoding: identity`.
2. Снять начальное значение `perf_counter()` непосредственно перед `urlopen()`.
3. Открыть ответ с тайм-аутом 30 секунд.
4. Читать тело блоками до конца ответа. После каждого чтения прибавлять `len(block)` к счётчику.
5. После чтения, установившего конец тела, снять конечное значение таймера, проверить полноту ответа и закрыть его.
6. Сохранить длительность и число байтов; только затем начать следующую загрузку.

Интервал включает установление соединения, TLS для HTTPS, редиректы, ожидание заголовков и чтение тела. Подготовка запроса, итоговый вывод и промежутки между загрузками исключены. Тело не накапливается в памяти и не записывается на диск.

Для длительности `tᵢ` и объёма `bᵢ` каждой загрузки:

```text
T = Σ tᵢ, i = 1…10
Среднее время = T / 10
Общий объём B = Σ bᵢ, i = 1…10
Средняя скорость = B / T / 1 048 576 MiB/s
```

Скорости отдельных запросов арифметически не усредняются. При неположительном `T` расчёт завершается ошибкой измерения.

**HTTP-поведение:**

- Используется стандартная обработка редиректов `urllib.request`. Десять логических загрузок могут породить больше десяти HTTP-обращений. Время переходов включается; объём учитывает только тело конечного ответа. Ошибка перенаправления прерывает замер.
- Запрашивается несжатое представление. `urllib.request` автоматически не распаковывает `Content-Encoding`; если сервер всё же возвращает сжатое тело, считаются прочитанные сжатые байты. Заголовки, TLS и служебные данные передачи в объём не входят.
- Тайм-аут относится к блокирующим сетевым операциям и не является общим пределом длительности загрузки: постепенно поступающий ответ может читаться дольше 30 секунд.
- Ошибка чтения означает неуспех. Если применим корректный `Content-Length`, после чтения он сравнивается со счётчиком для обнаружения усечения; источником объёма остаётся счётчик. При chunked-передаче полноту определяет завершение потока библиотекой. Для ответа, ограниченного закрытием соединения и не имеющего известной длины, отличить штатный конец от усечения невозможно.

## 5. Проверки и критерии приёмки

Использовать локальный HTTP-сервер и стандартный `unittest`, без отдельного тестового фреймворка.

Проверить:

- Сервер отдаёт известное тело размером больше двух блоков. Получены ровно 10 GET-запросов; следующая загрузка начинается после полного чтения предыдущей.
- Сервер отправляет тело несколькими порциями. Итоговый объём равен десятикратному размеру тела, в том числе без `Content-Length`.
- Для заранее заданных длительностей и объёмов расчёт соответствует формулам; неравные длительности выявляют ошибочное усреднение отдельных скоростей.
- HTTP 404 на четвёртой загрузке прекращает запуск: пятого запроса нет, успешного итога нет, код ненулевой.
- Неверный URL, отказ соединения, задержка сверх тестового тайм-аута и усечённый ответ дают понятные ошибки.
- Локальный редирект подтверждает различие между логическими загрузками и HTTP-обращениями.

Стабильная скорость внешнего сайта не является критерием приёмки.
